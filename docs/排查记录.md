# 排查记录：一次真实的桌面端故障

> 时间：2026-11-26
> 环境：Windows 11（Build 26300）+ ChatGPT 桌面版 26.1120.6357.0 + SakuraCat 代理（`127.0.0.1:12450`）
> 结果：核心故障消除，实测验收通过

这份记录的价值不在结论，而在**方法**——怎么从"间歇性、看起来随机"的症状，一步步定位到唯一原因。

---

## 一、初始症状

1. 生成的文件有时无法直接下载，强制跳转网页端，跳转后仍下载失败
2. 部分文件无法在桌面端预览
3. Work 本地执行环境频繁异常
4. 曾出现进入 Work 模式即报 Code 1
5. 本地执行环境无法通过代理访问互联网
6. 个人 Skill 安装与同步失败

看起来像五六个不同的 bug。**实际上是一个。**

---

## 二、排查原则

- 每个怀疑都要**用数据验证**，验证不了的不下结论
- 区分**产品设计**和**故障**——不是所有"不正常"都是 bug
- 先证明"不是它"，再证明"是它"
- 宁可留着不处理，也不做未经验证的破坏性操作

---

## 三、逐项排查

### 1. 代理链路

| 测试 | 结果 |
|---|---|
| 直连 `https://chatgpt.com` | 失败（HTTP 000，超时） |
| 走 `127.0.0.1:12450` | 成功（HTTP 200） |
| 网卡 | 只有 WLAN，**无 TUN 虚拟网卡** |
| 用户/系统环境变量 `HTTP_PROXY` | 空 |

**结论**：本机是系统代理模式，必须走代理，直连不通是正常的。

### 2. 桌面端是否读系统代理

扫描后端二进制中的字符串：

```
WinHttpGetIEProxyConfigForCurrentUser
Internet Settings / ProxyServer / ProxyEnable
HTTP_PROXY / HTTPS_PROXY / ALL_PROXY / NO_PROXY
dotenvy
```

**结论**：两套进程都读系统代理；后端还会加载 `.codex\.env`。

### 3. 日志分析（关键）

日志库共 37172 条，其中 ERROR 331 条。

按天分布：

| 日期 | ERROR | 备注 |
|---|---|---|
| 11-16 ~ 11-19 | 3 / 18 / 9 / 15 | 偶发 |
| **11-23** | **250** | 单日爆发 |
| 11-24 | 21 | |
| 11-25 | 15 | |
| 11-26（修复后） | 0 | |

**331 条 ERROR 只有三类**，全部指向"连不上 chatgpt.com"：

- MCP transport 连不上：178
- 模型列表超时：122
- 响应流 WebSocket 连不上：31

**决定性细节**：git 同步失败日志写着

```
Failed to connect to github.com:443 over proxy 127.0.0.1 after 1 ms:
Could not connect to server
```

`after 1 ms` = **端口根本没在监听**，不是网络慢。

### 4. 安装包与运行时

| 检查 | 结果 |
|---|---|
| Store 包状态 | `Ok` |
| 主程序签名 | `Valid` |
| `codex.exe` / `node.exe` | 均能正常执行 |
| config.toml 引用的运行时路径 | 全部存在 |
| config.toml 解析 | `ok` |

**结论**：安装完好，不是"装坏了"。

### 5. 配置与路径

- 已知文件夹（桌面/文档/下载）重定向正常
- 下载目录可写（实测写入+删除）
- 磁盘剩余 65 GB
- `.env` 代理变量齐全

### 6. EFS 加密

| 检查 | 结果 |
|---|---|
| 该应用包内文件 | **2907 / 2907 全部 EFS 加密** |
| 其他 MSIX 包（对照） | 0 / 400 加密 |
| 日志中 `Access is denied` / `os error 5` | **0 条** |

**结论**：状态异常，但**没有造成实际错误**。按"未验证到实际错误不批量解密"的原则，**未做处理**。

### 7. 其他常见嫌疑

| 怀疑 | 结果 |
|---|---|
| 受控文件夹访问拦截写盘 | 已关闭 |
| ASR 规则 | 0 条 |
| WebView2 版本不匹配 | 不适用（用的是内置 Chromium） |
| 浏览器下载被拦截 | 见第 9 项，根本没走浏览器下载 |

### 8. 沙箱网络实测

在官方沙箱里执行探测：

```
HTTP_PROXY 变量：存在
DIRECT 访问    ：000
走代理访问     ：000
写 %TEMP%      ：拒绝访问
```

再用配置开关放开（`sandbox_workspace_write.network_access=true`）→ **仍然 000**。

**结论**：防火墙级别的产品隔离，配置改不动，也不该改。

### 9. Chromium 下载数据库（决定性）

| 表 | 行数 |
|---|---|
| `downloads` | **0** |
| `downloads_url_chains` | **0** |
| `downloads_slices` | **0** |

**一次下载记录都没有**，但"下载"文件夹里确实有成功落盘的文件。

**结论**：下载由后端直接写盘，从不经过浏览器。所谓"跳网页"是另一条代码路径（`openExternal`）。

### 10. 开机与代理的时间线

| 事件 | 时间 |
|---|---|
| 开机 | 21:56 |
| 自检发现"代理端口未监听" | 21:57 |
| 手动启动代理软件 | 22:47 |
| **中间空白** | **52 分钟** |

并且**代理软件不在任何开机启动项里**。

**结论**：每次开机后、手动开代理之前，桌面端必然是坏的。**这不是偶发，是必然。**

## 四、根因

```
代理未运行 / 节点断开
      ↓
系统代理端口没有监听
      ↓
界面 + 后端 全部连不上 chatgpt.com
      ↓
模型超时、WebSocket 断开、MCP 连不上（那 331 条 ERROR）
      ↓
取不到文件 → 调用 openExternal → 跳浏览器
      ↓
浏览器无登录态 → 下载失败
```

**一个原因，解释了全部六个症状。**

## 五、修复

### 做的

| 动作 | 目的 |
|---|---|
| 完整备份配置 | 可回滚 |
| 清理崩溃残留临时文件 | 避免干扰状态加载 |
| 建立健康自检（10+ 项） | 30 秒定位到哪一环 |
| 建立每日配置快照 + 自动恢复 | config.toml 被清零时自愈 |
| 注册计划任务（登录后 3 分钟 + 每天） | 自动检测，代理没开就拉起 |
| 桌面「一键修复网络」 | 不用记命令 |
| 实测恢复机制（删掉配置 → 自动恢复 → 哈希一致） | 证明真能用，不是"应该能" |

### 刻意没做的

| 未做 | 原因 |
|---|---|
| 批量解密 EFS | 0 条访问错误，无证据支持 |
| 开启沙箱联网 | 防火墙级隔离，配置无效；且是产品安全设计 |
| 加杀毒软件排除项 | 会降低防护，当前无拦截证据 |
| 清理数据库 / 会话 | 风险高于收益 |
| 设全局代理环境变量 | **会造成倒退**：部分域名直连本来能通，设了反而全绕代理 |

## 七、可复用的经验

1. **症状多 ≠ 故障多**。先按错误消息归类，往往只有一类。
2. **`after 1 ms` 和 `timed out` 是两回事**。前者是端口没开，后者才是网络慢。
3. **"直连不通"不一定是配置错误**，可能本来就该走代理。
4. **看 Chromium 的下载表**能直接判断下载走的是哪条路径。
5. **沙箱没网是设计**，别当 bug 修。
6. **加密属性 ≠ 故障**，要看有没有实际访问错误。
7. **开机到代理启动的空档**是最容易被忽略的故障窗口。
