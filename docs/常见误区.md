# 常见误区

> 排查这类问题时，**大部分时间不是花在"修"，而是花在"排除错误的方向"**。
>
> 下面这些是真实踩过的坑。每一条都写成「你以为 → 实际上 → 怎么判断」，看完能省掉大量瞎折腾。

---

## 误区 1：我代理开着，所以网络没问题

**你以为**：托盘图标亮着、界面显示"已连接"，网络就是通的。

**实际上**：代理软件通常有两个进程——**界面进程**和**引擎进程**。你看到的是界面，真正干活的是引擎。

- 切节点、改规则、更新订阅、引擎崩溃自动拉起 → **引擎会单独重启**
- 重启那几秒，端口消失，所有在途请求瞬间失败
- 更隐蔽的：引擎在跑、端口也在监听，**但节点不回话**

这三种情况，界面都显示"已连接"。

**怎么判断**：别信界面，直接发一个请求：

```powershell
curl.exe -I --proxy http://127.0.0.1:端口 https://chatgpt.com
```

| 返回 | 含义 |
|---|---|
| `HTTP/1.1 200 Connection established` | 真的通 |
| 卡住不动，最后超时 | 节点问题（界面在骗你） |
| 立刻 `Could not connect` | 引擎没了 |

## 误区 2：直连打不开，说明我的网络坏了

**你以为**：`curl https://chatgpt.com` 不通 = 网络故障。

**实际上**：如果你的网络环境本身无法直连该站点，**直连失败是正常的**。

关键看有没有 **TUN 虚拟网卡**：

```powershell
Get-NetAdapter | Where-Object Status -eq 'Up'
```

- 有虚拟网卡（TUN / 全局模式）→ 所有流量被接管，直连也该通
- 只有真实网卡（系统代理模式）→ **必须走代理**，直连不通属于正常

**怎么判断**：直连失败 + 走代理成功 = 配置没问题，本来就该这样。

---

## 误区 3：沙箱里没网，说明工具坏了

**你以为**：在 Work / 沙箱里跑 `curl`、`git clone`、`npm install` 全失败，是安装坏了。

**实际上**：这是**产品安全设计**。受限沙箱默认同时限制文件系统和网络。

实测：沙箱内 `HTTP_PROXY` 变量明明在，请求依然返回 `000`；连 `%TEMP%` 都写不进去。

而且**改配置没用**——隔离在防火墙规则层面。官方诊断会明确显示：

```
✓ sandbox   restricted fs + restricted network
```

**怎么判断**：这是"设计如此"，不是"坏了"。需要联网的命令，走 App 的**授权/审批流程**在沙箱外执行。

**不要**为了这个去关沙箱、加防火墙放行、或用管理员权限硬跑。

---

## 误区 4：文件带加密属性，所以必须解密

**你以为**：看到文件属性里有 `Encrypted`，就是它在捣乱。

**实际上**：加密属性本身**不产生任何错误**。只有当程序以**不同用户身份**运行、拿不到解密密钥时，才会真的读不了。

判断顺序很重要：

1. 程序能启动、能读文件 → **不需要处理**
2. 日志里出现 `Access is denied` / `os error 5`，且指向该目录 → 才考虑

**怎么判断**：

```powershell
(Get-Item "C:\路径\文件.exe" -Force).Attributes
```

有 `Encrypted` 但一切正常 → 放着别动。

**警告**：绝不要对 `C:\Program Files\WindowsApps` 整个目录批量 `cipher /d`，那会破坏应用包。

## 误区 5：日志里几百条报错，说明有很多毛病

**你以为**：300 条 ERROR = 300 个问题。

**实际上**：往往只有**一个原因**，只是被不同的模块各报了一遍。

真实案例：331 条 ERROR 归完类只有三种——拉不到模型列表、连不上实时通道、连不上插件服务。**全是"连不上服务器"的三种说法。**

**怎么判断**：按**错误内容**归类，不要按条数看。

还有个技巧看**时间分布**：

| 形态 | 含义 |
|---|---|
| **尖峰聚集**（比如一分钟 152 条） | 瞬时事件（重启、切换） |
| **均匀铺开**（几小时内都有） | 持续性问题（节点长期不可用） |

---

## 误区 6：重装一遍总能解决

**你以为**：软件有问题，卸了重装最干净。

**实际上**：大多数情况下**问题不在安装**，重装解决不了，还会：

- 丢掉配置、项目授权、历史会话
- 覆盖掉现场证据，之后更难查
- 如果是网络/代理问题，重装后照样坏

**怎么判断**：先确认安装本身有没有问题——

- 包状态是否 `Ok`
- 主程序签名是否 `Valid`
- 关键可执行文件能否正常运行（`--version`）
- 配置里引用的运行时路径是否都存在

这几项都正常，就**不要重装**。

## 误区 7：点"下载"就是浏览器下载

**你以为**：桌面端点下载 = 走浏览器那套下载管理器。

**实际上**：桌面端通常是 Chromium 外壳 + 本机后端。文件是**后端直接写盘**的，根本不经过浏览器下载管理器。

证据：查 Chromium 的下载数据库，`downloads` 表**一条记录都没有**，即使成功下载过文件。

所以"跳浏览器"不是"下载失败的兜底 UI"，而是**另一条代码路径**（把链接丢给系统浏览器）。

**怎么判断**：浏览器里没登录态 → 跳过去必然失败。问题在"取不到文件"，不在"下载组件"。

---

## 误区 8："超时"和"连不上"是一回事

**你以为**：都是网络问题，处理方式一样。

**实际上**：差很远。

| 报错 | 含义 | 该查什么 |
|---|---|---|
| `timed out` | 连上了，但对方不回话 | **节点 / 线路**（换节点） |
| `Could not connect` / `after 1 ms` | 根本没连上 | **端口 / 引擎**（代理是否在跑） |

特别记住这个细节：

```
Could not connect to server ... after 1 ms
```

**1 毫秒**失败 ≠ 网络慢。1 毫秒意味着**门口没人**，端口压根没监听。

如果是网速问题，会写"超时 30 秒"。

## 误区 9：清缓存、删数据库是万能药

**你以为**：出问题就清缓存，反正能重建。

**实际上**：数据库里存着**会话历史、项目授权、队列任务**。删了就是真的没了。

而且很多时候问题根本不在缓存——清了没用，还丢了数据。

**怎么判断**：先看数据库**完整性**，而不是直接删。官方工具通常能报告 integrity 状态。

**原则**：能不删就不删；要删先备份。

---

## 误区 10：用管理员权限 / 关掉安全机制就能好

**你以为**：权限不够，提权就好了。

**实际上**：

- 沙箱限制是**产品权限模型**，提权绕过它 = 拆掉安全机制，而且下次更新就失效
- 杀毒软件的"受控文件夹访问"确实会拦写盘，但**先确认它真的开着**（很多机器上是关的）
- 关闭防护是最后手段，且要清楚风险

**怎么判断**：先查清楚是哪一层在拦，再决定要不要动。**能用官方配置项解决的，绝不改系统安全设置。**

---

## 误区 11：改完配置马上生效

**你以为**：改完 `config.toml` 就立刻起作用。

**实际上**：多数配置要**重启应用**才生效。有些设置（比如沙箱网络策略）甚至要重新建立会话。

**怎么判断**：改完 → 完全退出应用（不是最小化）→ 重新打开 → 再测。

---

## 误区 12：检查结果 HEALTHY 就代表一切正常

**你以为**：机器侧全绿，问题就不存在了。

**实际上**：`HEALTHY` 只代表**你这台机器上能查的环节都正常**。它不代表：

- 代理节点此刻可用（可能下一秒就断）
- 服务端没故障
- 客户端版本没有 bug

**怎么判断**：`HEALTHY` 但功能仍不正常 → 问题**不在你电脑上**。换节点、等更新、或去官方反馈。

## 一张速查表

| 你的直觉 | 更可能的事实 |
|---|---|
| 代理开着就没问题 | 引擎可能刚重启，或节点不回话 |
| 直连不通 = 网络坏 | 系统代理模式下这是正常的 |
| 沙箱没网 = 坏了 | 产品设计，改配置也没用 |
| 文件加密 = 要解密 | 没有访问错误就别动 |
| 300 条报错 = 300 个问题 | 往往只有一个原因 |
| 重装最干净 | 大多数时候没用，还会丢数据 |
| 下载 = 浏览器下载 | 后端直接写盘，跳浏览器是另一条路 |
| 超时 = 连不上 | 一个是节点问题，一个是端口问题 |
| 清缓存万能 | 会丢会话和历史 |
| 提权/关防护能解决 | 是拆安全机制，不是修问题 |
| 改配置立刻生效 | 多数要重启应用 |
| HEALTHY = 万事大吉 | 只代表本机能查的都正常 |
