# ChatGPT / Codex Windows 桌面端 修复工具

> 症状：**生成的文件下不下来、强制跳浏览器、Work 模式报 Code 1、执行器频繁中断、插件/Skill 同步失败**
>
> 大多数情况下的真实原因只有一个：**代理没在跑**，或者跑着但节点断了。

这是一个**诊断 + 自动恢复**工具包，不是"破解"或"绕过"。它只做三件事：查清楚哪一环坏了、能自动修的安全地修掉、修不了的说清楚原因。

---

## 先看这张表：你的症状对应什么

| 症状 | 最可能的原因 | 怎么办 |
|---|---|---|
| 生成的文件点下载 → 跳浏览器 | 代理断了，App 取不到文件，只能"用浏览器打开链接" | 双击桌面「一键修复网络」 |
| 跳浏览器后也下不下来 | 浏览器里没有 App 的登录态 | 同上，恢复代理后重试 |
| **我明明开着代理**，还是不行 | 引擎重启有秒级空窗；或节点不通但界面仍显示"已连接" | 见 [为什么代理开着还是不通](docs/原理说明.md#为什么代理明明开着还是不通) |
| 一进 Work 模式就报 **Code 1** | 本地执行器起不来（常见于代理未就绪 / 配置被清零） | 同上 |
| 模型列表转圈、一直超时 | 连不上 `chatgpt.com` | 检查代理节点 |
| 插件 / Skill 同步失败 | 同上（远端目录拉不下来） | 检查代理节点 |
| 沙箱里跑 `curl` / `git` 没网 | **正常现象**，见 [原理说明](docs/原理说明.md#沙箱为什么没有网络) | 用 App 的授权流程，别去关沙箱 |
| 文件明明能读，但程序报"拒绝访问" | 可能是 EFS 加密（少见） | 见 [原理说明](docs/原理说明.md#efs-加密) |

> **重要**：代理界面显示"已连接"**不代表线路是通的**。代理通常由"界面进程"和"引擎进程"两个组成，引擎会单独重启；节点挂了端口也照样在监听。
> 判断方法只有一个——**真的发一个请求出去看能不能回来**，这正是本工具做的第二关检查。

## 快速开始（3 步）

### 1. 克隆仓库

```powershell
git clone https://github.com/Hunhung/chatgpt-windows-fix.git
cd chatgpt-windows-fix
```

### 2. 运行安装脚本

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

它会：复制工具到 `%USERPROFILE%\CodexFix` → 备份你当前的配置 → 注册计划任务（登录后 3 分钟 + 每天 12:30 自动自检）→ 在桌面建「一键修复网络」快捷方式 → 立刻跑一次自检。

### 3. 以后出问题

**双击桌面「一键修复网络」**，看最后一行结论：

| 结论 | 含义 |
|---|---|
| `HEALTHY` | 机器侧没问题 → 问题在代理节点或服务端，换节点重试 |
| `REPAIRED` | 发现并自动修好了（例如配置被清零） |
| `PROBLEM` | 有未修复的问题，按"问题清单"处理 |

## 不想装？只想查一下

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\codex-health.ps1
```

只检查、不改动任何东西。结果会写到 `scripts\reports\latest.txt`。

## 它会检查什么

| # | 检查项 | 说明 |
|---|---|---|
| 1 | 代理端口是否监听 + 引擎是否刚重启 | 从注册表读系统代理并解析 host:port；持有端口的进程启动不足 60 秒时提示"可能有空窗" |
| 2 | 经代理能否**真实**访问 chatgpt.com | 任何 HTTP 状态码都算通，`000` 才算失败。只查端口会被"界面显示已连接"骗过去 |
| 3 | `config.toml` 是否存在且未被清零 | 历史上出现过被写成 0 字节的情况 |
| 4 | `.env` 里的代理变量是否齐全 | Codex 靠它给子进程注入代理 |
| 5 | 桌面端安装包状态 + 主程序签名 | Store 包是否 `Ok`、签名是否 `Valid` |
| 6 | `config.toml` 引用的运行时是否都在 | node / codex / node_repl 等 |
| 7 | 下载目录是否可写 | 自动识别被重定向的"下载"文件夹 |
| 8 | 磁盘剩余空间 | |
| 9 | 崩溃残留临时文件 | `*.tmp-*`，可安全清理 |
| 10 | EFS 加密提示 | **只提示，绝不自动解密** |

---

## 它**不会**做什么

明确写在这里，避免误会：

- ❌ 不删除 `.codex` 目录
- ❌ 不清理数据库、不删会话历史
- ❌ 不批量解除 EFS 加密
- ❌ 不修改或关闭 Windows Defender / 受控文件夹访问
- ❌ 不关闭或绕过 Codex 的沙箱
- ❌ 不上传任何数据、不读取登录凭证

## 常用参数

```powershell
# 只检查
.\scripts\codex-health.ps1

# 检查 + 自动修复（配置被清零、崩溃残留）
.\scripts\codex-health.ps1 -Fix

# 额外允许"代理没开就自动拉起代理软件"
.\scripts\codex-health.ps1 -Fix -StartProxy

# 代理软件不在常见位置时，手动指定
.\scripts\codex-health.ps1 -StartProxy -ProxyExe "C:\路径\你的代理.exe"

# 配置整体回滚
.\scripts\restore-config.ps1
```

## 环境要求

- Windows 10 / 11
- PowerShell 5.1（系统自带）
- `curl.exe`（Windows 10 1803+ 自带）
- Git（仅克隆时需要）

不需要管理员权限。计划任务注册在当前用户下。

---

## 关于"能不能保证修好"

**不能保证。** 客户端更新、服务端故障、代理节点失效，这些不是本机工具能控制的。

这个工具能保证的是：**出问题时，30 秒内告诉你是哪一环坏了**，而不是让你对着一堆日志猜。

如果检查结果是 `HEALTHY` 但功能仍不正常，那问题基本不在你电脑上——换代理节点、等客户端更新、或者去官方反馈。
